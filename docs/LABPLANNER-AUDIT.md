# What the labplanner actually consists of

**An inventory taken 2026-09-21, before writing a skill over it.** JCA: *"We realized we needed
overarching 'skills' that wrap everything and guide the llm through the tools and how to use them,
pulling their names into context, after we made labplanner. So, it makes sense that we would just
have a bag of stuff right now with no wrapper."*

This counts the bag. It proposes nothing; §7 lists what a wrapper would have to say, which is a
different document.

**How this audit started is itself a finding.** A session asked `c11 which "how to use the labsheet
tools, all of them, start to finish"` and got `cf.check` at 0.82 — noise — and concluded out loud
that the toolkit had no documentation. It has 3,492 lines of it. The same index, asked
`"compile labsheets from a construction file"`, returns `cortex.labsheets` at **53.65**. Everything
below is reachable; §6 is about why it did not feel that way.

## 3. The generated records — 356

One per exported function carrying a JSDoc comment, written by `c6-sharables` from the comment
itself and checked for drift by `npm test`. By module: `plan` 81, `labplanner` 54, `inv` 53, `c6`
49, `model` 28, `protocol` 26, `seq` 15, `design` 12, `oligo` 11.

**These are a reference, not a route.** `chooseOverhang`, `describeTube`, `clone_max`, `everyRule` —
findable by name, useless for "how does this fit together". They are also the reason §6.1 happens:
163 of them carry the noun `labsheet`, so the exact index answers that noun with the compiler's
insides.

**82 exported functions have no record**, by design — the generator refuses to invent a description
from a function name, *"a wrong description is worse than an inventory that is missing one."*

## 5. There is already a wrapper, and it is the thing that rots

`experiment.author` describes the entire workflow — *"name it, design the oligos, write the
construction file… simulate and check both, answer what the compiler will not decide, compile the
labsheets, issue them, and record what came back."* Its own notes call it **"the one record that
says how these tools fit together."**

Three things are wrong with it, and they are the case for §7:

1. **It is typed `function` with `entry: c6-plan`.** Pressing the record that describes nine stages
   runs one of them. Nothing says so.
2. **It has been rewritten twice for going stale**, both times recorded in its own notes: first it
   *"described a toolkit that no longer existed and referred to 'the procedure below' while carrying
   no steps at all"*; then it *"stopped at 'compile the labsheets' — three steps before the workflow
   ends,"* so nothing connected `c6-issue` and `c6-receive` to anything a session would read.
3. **Nothing checks it against the store.** It is prose in a record, and prose in a record is the
   kernel's named failure: a true-sounding sentence with nothing enforcing it.

`b144.flow`, in cortex, is the same idea done the other way, and its `requires` is the whole
difference: *"it reads every `b144.*` record, so the map cannot go stale."*

## 6. Why the bag does not surface as a workflow

### 6.1 Eight front doors, seven nouns

| record | noun |
|---|---|
| `labsheet.compile`, `labsheet.schema` | `labsheet` |
| `labsheet.decide` | `decision` |
| `labsheet.issue`, `labsheet.holds` | `hold` |
| `labsheet.receive` | `inventory` |
| `labsheet.scenarios` | `scenario` |
| `cf.check`, `cf.sim`, `cf.plan` | `construction-file` |

Every one of those nouns is defensible on its own — `receive` really is about inventory, `issue`
really is about a hold. **The consequence is that no noun holds the workflow.** `ontology labsheet`
returns 166 records, 163 of them compiler internals, and misses five of the eight entry points.

### 6.2 The generated records own the vocabulary

The kernel: *"Vocabulary is shared and rivalrous. A record that grabs generic words takes them from
every record that could have matched them."* 356 generated descriptions, written for correctness
about one function, sit in the same ranked index as ten front doors.

### 6.3 A meta-question has nothing to rank against

`which` ranks what capabilities DO. "How do I use these tools" names no capability, so it returns
whatever shares a word. This is the failure at the top of this file, and no amount of indexing fixes
it — it is what a skill record is for.

## 7. What a wrapper would have to carry

Not built. Listed so the next session does not have to re-derive it:

- **The flow, in order**, with the verb that owns each stage: check → sim → plan → decide → compile
  → issue → receive → holds.
- **What each must NOT be used for** — the `invariants` field of `c11.skill`, which exists because
  a rule true of a SCOPE belongs to no single record. Candidates already written down elsewhere:
  an experiment with no characterization file STOPS, and `--clone-only` is how you say it ends at a
  verified plasmid; `--inventory` takes a DIRECTORY, and given one file every box in every other
  file is invisible.
- **Which records are front doors and which are internals** — 10 against 356, currently
  indistinguishable to a ranked lookup.
- **Derived, not written.** Every claim above about counts and nouns came from reading the store; a
  wrapper that restates them by hand is `experiment.author` again, and will rot the same way.

`c11.skill` is the schema for exactly this and **nothing in cortex, C6 or Pimar conforms to it.**
